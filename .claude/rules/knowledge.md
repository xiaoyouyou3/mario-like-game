# ナレッジの書式基準

| 項目 | 基準 |
|---|---|
| ファイル名 | `KN-NNN-<slug>.md`。NNN は 3 桁。ID は再利用せず、欠番は詰めない。slug は英小文字とハイフン |
| 見出し | `# KN-NNN <症状>` の下に、情報の表（分類・確度・関連・記録日）と、症状 / 原因 / 対処 / 再発防止 / 根拠の各節を、この順に置く |
| 分類 | ビルド / ローカル配信 / Git / 検証 / 要件・設計の見落とし / レビュー / テスト / Claude の振る舞い のいずれか。足りなければ、README.md の分類にも足す |
| 確度 | 「確認済み」「推測」「原因は推測・対処は確認済み」のいずれか。推測を断定で書かない |
| 根拠 | 実行したコマンドと、出力の要点（数値・エラー文）。「通ったはず」「たぶん」だけは不可 |
| 再発防止 | 次に同じ状況で何をするかを、命令形で 1〜2 文で書く。抽象論（「注意する」）は不可 |
| 個人情報 | ユーザーの名前・メールアドレス・認証情報・非公開の URL を書かない |
| 索引 | 新しい件を作ったら、README.md の一覧に 1 行足す。症状は 1 行で |
| 変更 | 誤りだった件は削除せず、「訂正（日付）」の節を足す。同じ学びは新規作成せず更新する |
| 重複 | 同じ内容を CLAUDE.md や rules にも書く（昇格）ときは、ナレッジからリンクを張り、本文は重複させない |
