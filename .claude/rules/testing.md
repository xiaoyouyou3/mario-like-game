# テストポリシー

## 原則
| 原則 | 基準 |
|---|---|
| Given-When-Then | 各テストは準備 / 実行 / 検証の3ブロックに分け、空行で区切る |
| 1テスト1振る舞い | 1テスト関数のアサーションは同一の振る舞いに関するものだけ |
| 振る舞いを検証 | 公開された関数・属性の結果を検証する。`_private` への依存は不可 |
| 決定的 | 実時間・乱数・ウィンドウ・ファイルシステムに依存しない。時間は `dt` 引数、乱数は注入 |
| 独立 | テスト間で状態を共有しない。実行順序に依存しない |
| 浮動小数 | `pytest.approx` を使う。`==` で比較しない |
| 境界値 | 閾値のある振る舞いは境界の前・上・後の3点を `pytest.mark.parametrize` で検証 |

## 弱いアサーション（REJECT 対象）
- `assert x`（真偽のみ）、`assert x is not None` のみ、`assert len(x) > 0` のみ
- 期待値を実装と同じ式で計算している（`assert v == GRAVITY * dt` で定数を再利用 等）。期待値は手計算した具体値で書く
- 例外を検証するのに `pytest.raises(Exception)`。具体的な例外型と `match=` を指定する

## テストダブル
- 直接の依存だけを差し替える。純粋関数はモックしない。
- モックが3つ以上要るなら、テスト対象の設計を疑う（設計の指摘事項にする）。
- 差し替え物は本番と同じ戻り値の形（shape）を返す。

## TC との対応
- テスト関数の直前行に `# TC-NNN`（複数可: `# TC-003, TC-004`）。
- テスト仕様書にないテストは書かない。必要と気付いたら、まず仕様書に TC を追加する。

## テストを追加しなくてよいケース
描画・音・入力デバイス・ウィンドウ生成のみに関わる変更（`src/render/`, `src/main.py`）は自動テスト対象外。代わりに `docs/test-specs/test-spec.md` の「手動確認」欄に項目を書く。
