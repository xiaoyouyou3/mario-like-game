# ゲーム実装の定石（マリオ風 2D アクション）

数値は **初期値案**。要件・設計で確定した値が優先。設計書の定数表に集約すること。

## 基準値（内部解像度 256x240, タイル 16px, 60FPS）
| 項目 | 初期値案 | 単位 | 備考 |
|---|---|---|---|
| 歩行最大速度 | 90 | px/s | ダッシュ時 150 |
| 水平加速度 | 720 | px/s^2 | 0→最大まで 0.125 秒 |
| 減速（入力なし） | 900 | px/s^2 | 地上のみ。空中は 360 |
| 重力 | 900 | px/s^2 | |
| ジャンプ初速 | 350 | px/s | 到達高さ v^2/2g ≒ 68px(約4タイル) |
| 落下終端速度 | 400 | px/s | |
| 可変ジャンプ | 上昇中にボタンを離したら vel.y *= 0.5 | - | 1回だけ適用 |
| コヨーテタイム | 0.08 | s | 離地後もジャンプ可 |
| ジャンプバッファ | 0.10 | s | 着地前の入力を保持 |
| 踏みつけ反発 | 200 | px/s | |

## 時間
- ロジックは `dt` を受け取る。ただし 1 回の更新に渡す dt は上限（例: 1/30）で切り詰めるか、固定タイムステップ(1/60) のアキュムレータで刻む。そうしないと低FPS時に壁をすり抜ける。
- 検証: dt=1/60 を 60 回 と、dt=1/30 を 30 回 で位置が許容誤差内で一致すること。

## 衝突（タイルマップ × AABB）
1. **軸を分けて解決する**: X方向に動かす → X方向の衝突を解決 → Y方向に動かす → Y方向の衝突を解決。同時に動かすと角で引っかかる。
2. 衝突の判定は「移動後の矩形が重なる固体タイル」を列挙して行う。1フレームの移動量 < タイルサイズ(16px) を保証すると、すり抜けが起きない。
3. 解決: X移動中なら、右へ動いていれば `player.right = tile.left`、左なら `player.left = tile.right`、vel.x = 0。Y移動中は下へ動いていれば `player.bottom = tile.top` かつ `on_ground = True`、上なら `player.top = tile.bottom`、vel.y = 0。
4. `on_ground` は毎フレーム「Y解決で下方向衝突が起きたか」から再計算する。持ち越さない。
5. 整数座標のタイル判定には `floor` を使う。負の座標で `int()` を使うと0方向に丸まり誤判定する。

## 敵との衝突
- 踏みつけ判定: プレイヤーが下降中(`vel.y > 0`)で、**前フレームの**プレイヤー底面 ≦ 敵上面(+許容 4px)。満たさなければ被ダメージ。
- 敵の反転: 進行方向の前方に壁タイル、または足元前方に床なし（崖）で反転。
- 判定順: 敵更新 → プレイヤーと敵の衝突解決。順序を設計書の更新順序と一致させる。

## カメラ
- `camera_x = clamp(player.x - SCREEN_W/2, max(camera_x_prev, 0), level_w - SCREEN_W)` のように、**左へ戻らない**・ステージ端でクランプ。

## テストしやすい書き方
- 入力は `InputState` データクラス、ステージは文字列の配列(`["....", "####"]`)から作れるようにすると、テストで小さなステージを直接書ける。
- 乱数を使う処理（敵のランダム挙動など）は `random.Random(seed)` を注入する。
