# ナレッジの記録と参照

置き場所は `docs/knowledge/`。索引は `README.md`、1 件 1 ファイル `KN-NNN-<slug>.md`。書式の基準は `.claude/rules/knowledge.md`（対象ファイルを触ると自動で読まれる）。

## 参照（作業の前）
1. `docs/knowledge/README.md` の一覧を見て、今の作業の分類（ビルド / ローカル配信 / Git / 検証 / 要件・設計の見落とし / レビュー / テスト / Claude の振る舞い）に該当する件を探す。
2. 該当する件だけを開く。全件は読まない。
3. 対処や再発防止が書かれていれば、それに従う。従った場合は、その件の「根拠」に、再び役立ったことを 1 行足してよい（昇格の判断に使う）。

## 記録（失敗が解決したとき）
次のタイミングで、記録の**候補を提案する**。**ファイルへの書き込みは、人間が承認してから**行う。
- 失敗や詰まりが解決したとき
- ユーザーから、やり方や結果について指摘されたとき
- レビューで REJECT になったとき、差戻しが起きたとき
- 工程が完了したとき（振り返り）

手順:
1. 既存の件を索引で検索する。同じ学びがあれば**新規作成せず、その件を更新する**。
2. 提案を会話で示す: 分類・症状・原因・対処・再発防止・根拠・確度（下記）。
3. 承認されたら、`docs/knowledge/KN-NNN-<slug>.md` を作り（NNN は最大の ID + 1。欠番は詰めない）、`README.md` の一覧に 1 行足す。
4. 記録したことを、会話で 1 行で伝える。

## 書き方の要点
- **事実と推測を分ける。** 確度の欄は「確認済み」「推測」「原因は推測・対処は確認済み」のいずれかにする。確認していない原因を、断定で書かない。
- **根拠を残す。** 実行したコマンドと、その出力の要点（数値・エラー文）を書く。「通ったはず」で書かない。
- **個人情報を書かない。** ユーザーの名前・メールアドレス・認証情報・内部の URL を書かない。リポジトリの公開 URL は可。
- 1 件 1 振る舞い（1 つの症状と、その原因と対処）。複数の症状を 1 件に束ねない。

## 昇格
同じ学びを 2 回以上参照した、または同じ失敗が再発したときは、`.claude/rules/`（守る基準）か該当する Skill（手順）に昇格することを提案する。昇格後も、ナレッジの件は残し、昇格先へのリンクを足す。ルールや Skill の変更は、人間の承認を得てから行う。

## 禁止
- 承認なしに `docs/knowledge/` へ書き込む。
- 確認していない推測を「確認済み」として書く。
- 既存の件を削除する。誤りだった件は、削除せず「訂正」を追記する。
