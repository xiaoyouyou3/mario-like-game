# 要件定義

基準は `.claude/rules/docs.md`（禁止語・受入条件の書き方）。新規作成前に既存の requirements.md があれば読む。

## 手順
1. **ヒアリング**: [references/interview.md](references/interview.md) の質問バンクから、未決の領域を **1回3問まで** 聞く。選択肢と推奨を添える。回答が曖昧なら数値で再質問する。推測で埋めない。
2. **執筆**: [templates/requirements.md](templates/requirements.md) をコピーして埋める。
   - 機能要件はマリオ風ゲームの最小構成チェックリスト（interview.md 末尾）を漏れなくカバーする。
   - 1要件=1文=1つの受入条件。受入条件はそのまま TC の期待結果にできる形にする。
3. **セルフチェック**（レビュー依頼前に実行）:
   - `grep -nE "快適|適切|スムーズ|素早|簡単|など|等|必要に応じて" docs/requirements/requirements.md` → 該当ゼロ
   - 全 REQ に受入条件（数値または真偽判定可能な条件）がある
   - 要件にクラス名・ライブラリ名がない
4. `docs/STATE.md` を更新し、**人間にレビューと承認を依頼**する。承認前に `requirements-reviewer` を呼んでよい（人間の負担軽減のため推奨）。
5. 承認されたら STATE.md の承認ログを更新する。承認後の変更は「変更要求」として REQ を追加・廃止で扱う。

## 禁止
- 承認前に基本設計へ進む。
- ユーザーが答えていない仕様（敵の種類数、ステージ数など）を勝手に決めて確定扱いにする。仮置きするなら「未決事項」に質問として残す。
