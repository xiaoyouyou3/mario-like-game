# 要件定義レビュー基準

入力: `docs/requirements/requirements.md`。共通ルールは `review-common`。IDプレフィックス: `REQ-R`。

## 先に実行する検証コマンド
```bash
grep -nE "快適|適切|スムーズ|素早|簡単|など|等|必要に応じて|高速|低遅延" docs/requirements/requirements.md   # 禁止語
grep -cE "^\| REQ-[0-9]+ " docs/requirements/requirements.md                                              # 要件数
grep -nE "pygame|class |関数|クラス|numpy|アルゴリズム" docs/requirements/requirements.md                 # How 混入
```

## 基準表（✕ は Must）
| 観点 | 合格基準 | Must にする例 |
|---|---|---|
| 検証可能性 | 全 REQ の受入条件が、数値または真偽判定できる条件で書かれている | 「操作しやすい」「滑らかに動く」だけの受入条件 |
| 単一性 | 1 REQ = 1 文 = 1 つの受入条件 | 「移動とジャンプができる」を1要件に束ねている |
| 一意性・矛盾 | ID が重複しない。要件同士が矛盾しない | REQ-003 が「残機3」、REQ-009 が「1回で終了」 |
| How 混入 | 実装手段が書かれていない | 「pygame の Rect で判定する」 |
| 完全性 | 最小構成チェックリスト（移動・ジャンプ・衝突・敵・踏みつけ・被ダメージ・落下死・ゴール・ゲームオーバー・カメラ）が REQ または「含まない」に明記 | ゴール条件の記述がなく、含まないとも書かれていない |
| スコープ | 「含む」「含まない」が書かれ、各 REQ に優先度がある | Must が全体の 8 割超で優先度が機能していない（Should） |
| 非機能 | FPS・画面サイズ・対応OS が数値で書かれている | 「軽快に動く」のみ |
| 未決事項 | 不明点が推測で埋められず、未決事項に残っている | 未回答のはずの項目（敵の種類数など）が確定値として書かれている |
| 用語 | 同じものを同じ語で呼んでいる | 「プレイヤー」「キャラ」「主人公」が混在（Should） |

## 判定の注意
- 要件が少ない・小さいことは欠陥ではない。スコープ宣言と整合していれば APPROVE。
- 「面白いか」「ゲームバランス」は要件レビューの対象外。
