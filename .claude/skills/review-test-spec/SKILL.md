# テスト仕様書レビュー基準

入力: `docs/test-specs/test-spec.md`、上流 `docs/design/basic-design.md` `docs/requirements/requirements.md`。IDプレフィックス: `SPEC-R`。
このレビューは「詳細設計としてのレビュー」を兼ねる: **この仕様書だけを読んで実装者が迷わず実装できるか** を問う。

## 先に実行する検証コマンド
```bash
.venv/bin/python scripts/trace_check.py --stage spec     # 全 REQ が TC に紐づくか
grep -nE "正常に|正しく|適切|問題なく|エラーにならない" docs/test-specs/test-spec.md   # 曖昧な期待結果
```

## 基準表（✕ は Must）
| 観点 | 合格基準 | Must にする例 |
|---|---|---|
| 網羅（REQ） | trace_check が OK。Must 優先度の REQ は正常系 TC に加え、境界または異常の TC がある | Must の REQ-003 に正常系 TC しかない |
| 網羅（DES） | 全 DES に TC がある | DES-004(カメラ) に TC がない |
| 期待結果の具体性 | 数値・状態で書かれ、自動判定できる | 「正しく移動する」 |
| 計算根拠 | 数値の期待結果に備考で手計算の根拠がある | `vel.x == 12.0` の根拠が不明で、定数表と合わない |
| 定数との整合 | 期待値が基本設計の定数表の値から導出できる | ACCEL=720 なのに期待値が 15.0 |
| 単一性 | 1 TC = 1 When = 1 つの振る舞い | When に「右に歩いてジャンプする」 |
| 境界値 | 閾値のある振る舞いに「直前/ちょうど/直後」の3点がある | 最大速度の TC が 1 点のみ |
| 状態遷移 | 全遷移と主な禁止遷移に TC がある | 死亡中のジャンプ無視が未定義 |
| 時間 | dt 分割の一貫性、dt=0、大きな dt の TC がある | すり抜け防止の TC がない（衝突を扱う場合） |
| ロジック限定 | 自動 TC が描画・実時間・ウィンドウに依存していない | 「画面に表示される」が自動 TC にある |
| グループ | TC が 1〜5 個のグループに分かれ、グループ名が振る舞いを表す | 全 TC が1グループ（TDDサイクルが回せない・Should） |
| 実装可能性 | 実装者が追加の質問なしに実装できる（不足する前提・用語がない） | 「ブロックに当たったとき」の「当たる」の定義がない |
| 手動確認 | 自動化しない項目が手動確認欄に合格基準つきで分離されている | 操作感が自動 TC に混在 |

## 判定の注意
- TC 数の多さは目的ではない。重複 TC は Should（同じ失敗でしか落ちないもの）。
- 仕様書にない新規要件を要求しない（要件の欠陥は「上流への差戻し」として Must の理由に書く）。
